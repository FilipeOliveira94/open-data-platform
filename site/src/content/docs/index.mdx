A number in a report should have a path you can follow, from the source to the person who uses it. The Open Data Platform builds that path with open-source parts only: raw files and API responses land in object storage, Spark and dbt refine them through Bronze, Silver and Gold Iceberg tables, Trino reads them, and Airflow runs the schedule. Everything runs locally on Windows 11, WSL2 and Docker Compose. There is no cloud deployment path ([ADR-0029](https://github.com/FilipeOliveira94/open-data-platform/blob/main/docs/decisions/0029-open-source-only-platform.md)).

## What runs today

- **Five sources, one raw layout.** Olist CSV files, the DummyJSON and IBGE APIs, a windowed extract of the olist-synth-cdc PostgreSQL database, and a generated storefront clickstream land in MinIO under `raw/{source}/{dataset}/dt=…/execution_id=…/`.
- **Contracts before the load.** Each dataset has a YAML contract. Invalid rows stay in the raw object, and their findings go to a quarantine sidecar.
- **A medallion lakehouse.** Spark writes Bronze and Silver Iceberg tables, dbt-trino builds the Gold marts, and Trino reads every layer. See [Architecture](./architecture/).
- **Scheduled batch.** Airflow runs a daily extract and a weekly re-extract of late commits, refreshes the API sources, and starts the lakehouse refresh from a raw Asset. A failed layer check blocks the next layer.
- **CI on every change.** GitHub Actions runs Ruff, the Markdown table check and the unit tests, with no cloud credentials.

Streaming CDC, observability, lineage, the notebooks and dashboards, and the figures on this site are planned. Each arrives with its phase.
