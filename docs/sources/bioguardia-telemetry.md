# BioGuardia telemetry stream

| Field | Value |
| --- | --- |
| Name | BioGuardia telemetry gateway stream |
| Type | Generated event stream on Kafka (JSON messages) |
| Role | Readings, health, and alerts of about 33,300 field devices of a fictitious environmental agency, published 24/7 |
| URL | None. The producer is local (`open_data_platform.simulators.bioguardia telemetry run`) |
| Gold Domain | Planned in Phase 11: wildfire response, watershed monitoring, stream reconciliation (P11-12, P11-13) |
| License | Generated by this repository |
| Access | Kafka `kafka:9092` on the Compose network, `localhost:9094` from the host; Compose services `kafka`, `kafka-init`, `bioguardia-telemetry` (profile `streaming`); `make stream-up` |
| Decision | [ADR-0027](../decisions/0027-bioguardia-synthetic-sources.md) (source), [ADR-0028](../decisions/0028-telemetry-message-broker.md) (broker) |
| Related Issue | P11-03 (producer and broker); P11-04 and P11-09 (consumers, not built) |

The producer replays the same world model as the [daily export](bioguardia-ops-export.md). The devices in the `devices` snapshot are the devices that emit here, and `device_daily_counters` counts, per device and UTC day, what this stream must carry: `readings_generated + health_generated + alerts_generated - messages_dropped` distinct events.

## Topics

| Topic | Partitions | Per hour at scale 1 | Content |
| --- | --- | --- | --- |
| `bioguardia.telemetry.readings.v1` | 6 | About 540,000 | Sensor readings: smoke and heat every 120 s, weather and river gauges every 60 s, soil moisture every 300 s |
| `bioguardia.telemetry.health.v1` | 3 | About 485,000 | Device health every 240 s, every device type |
| `bioguardia.telemetry.alerts.v1` | 3 | Bursts | Alerts raised on the device |
| `bioguardia.telemetry.gateway.v1` | 1 | One per restart | Gateway restart and skip records |

The message key is `device_id`, so one device's events keep their order inside a partition. Retention is `ODP_KAFKA_RETENTION_HOURS` (default 72) with a `retention.bytes` cap per partition (4 GiB for readings and health, 1 GiB for alerts and gateway). Messages are JSON, UTF-8, compressed with zstd by the producer. The model's baseline is about 1.03M events per hour at scale 1 (P11-03 measures it); fire bursts and chattering devices add to it.

## Delivery semantics

- **Identity:** `event_id` is `{device_id}-{yyyymmdd}-{R|H|A}{seq}`: the UTC day, the stream letter, and the event's position in that device's stream for that day. It is the dedupe key.
- **Times:** `event_time` is the device clock (UTC, milliseconds). `gateway_time` is when the gateway sent the event. They differ by 0 to 2 seconds normally.
- **Late events:** a device that loses connectivity (about 1.5% of devices per day, median 3 hours, at most 18 hours each; overlapping outages merge into one) keeps its messages for `ODP_TELEMETRY_BUFFER_HOURS` (12; 1 to 24) and uploads them when it reconnects, all at once. Messages older than the buffer are lost on the device and counted in `device_daily_counters.messages_dropped`.
- **Duplicates:** about 0.1% of events are retransmitted 3 to 8 seconds later with the same `event_id`. A producer restart also re-sends the messages sent after its last checkpoint: at most 5 seconds of sending, which is about 1,400 events at the live rate but up to 100,000 while the producer is catching up at 20,000 per second. On 2026-11-26 a crash during a catch-up re-sent about 2.8 minutes of traffic (47,185 copies in a 40-minute window); every event was still present.
- **Out of order:** latency jitter and outage uploads deliver events out of `event_time` order across devices, and uploads arrive hours late.
- **Clock skew:** on some days a few devices report `event_time` two hours ahead, or counted from 2000-01-01, for one to six hours. The planted list names them.
- **Bursts:** while a fire burns in a zone, its smoke sensors send a reading every second; on some days a few smoke or weather devices "chatter" at 30 times their cadence for two to six hours.
- **Raw values:** the primary metric of each reading is uncalibrated: `calibrated = raw * calibration_gain + calibration_offset`, using the device calibration in force at `event_time` (`devices.calibrated_at`). Primary metrics: `smoke_ppm` (smoke_heat), `temp_c` (weather), `water_level_cm` (river_gauge), `vwc_pct` (soil_moisture). Other metrics are factory-calibrated.

## Producer restarts and the gateway topic

The producer checkpoints, every 5 seconds, the last second whose messages Kafka acknowledged (`/var/lib/bioguardia/telemetry-checkpoint.json` on the volume `odp_telemetry_state`). On start:

- If it is less than two minutes behind, it continues from the checkpoint (some messages are re-sent).
- Otherwise the gateway was down. It replays the messages scheduled since the checkpoint whose event time is inside the device buffer, at up to 20,000 per second, and skips the older ones the way a device loses them. It writes a `restart` record with the counts and windows, and `skipped_detail` records with the skipped counts per device and UTC day (chunks of 5,000 devices).

If the checkpoint file exists but cannot be read, the producer starts from the current time and writes a `checkpoint_unreadable` record, so the gap shows up as unexplained loss with a cause on record.

Reconciliation (P11-12) classifies each missing event: dropped on the device (counters), skipped by the gateway (this topic), or unexplained.

## Message fields

| Field | Topics | Description |
| --- | --- | --- |
| `event_id` | readings, health, alerts | Dedupe key, see above |
| `schema_version` | all | 1 |
| `device_id` | readings, health, alerts | Device; joins `devices.device_id` |
| `device_type` | readings, health, alerts | smoke_heat, weather, river_gauge, soil_moisture, acoustic, camera_trap |
| `stream` | readings, health, alerts | readings, health, or alerts |
| `seq` | readings, health, alerts | Position in the device's stream for the UTC day, from 0 |
| `event_time` | readings, health, alerts | Device clock, ISO-8601 UTC with milliseconds |
| `gateway_time` | readings, health, alerts | Send time, ISO-8601 UTC with milliseconds |
| `firmware_version` | readings, health, alerts | Firmware at the start of the UTC day |
| `metrics` | readings | Object of numeric values by metric (below) |
| `battery_pct` | readings, health | Battery level |
| `rssi_dbm` | readings, health | Radio signal strength |
| `solar_w` | health | Solar panel output |
| `uptime_s` | health | Seconds since installation |
| `storage_free_mb` | health | Free local storage |
| `enclosure_temp_c` | health | Temperature inside the enclosure |
| `alert_type` | alerts | smoke_alarm, heat_spike, chainsaw, gunshot, vehicle, water_level_high, water_level_critical, human_presence, tamper, low_battery |
| `severity` | alerts | 1 to 5 |
| `confidence` | alerts | 0 to 1 |

Metrics by device type: smoke_heat `smoke_ppm`, `temp_c`, `humidity_pct`; weather `temp_c`, `humidity_pct`, `wind_speed_ms`, `wind_dir_deg`, `pressure_hpa`, `rain_mm`; river_gauge `water_level_cm`, `water_temp_c`, `turbidity_ntu`; soil_moisture `vwc_pct`, `soil_temp_c`. Acoustic recorders and camera traps send health and alerts only.

Gateway records (`bioguardia.telemetry.gateway.v1`, key `record_id`):

| Field | Record | Description |
| --- | --- | --- |
| `record_id` | both | `gw-{restart epoch}` and, for details, the UTC date and chunk |
| `record_type` | both | restart, skipped_detail, checkpoint_unreadable, or gap_too_long (a stop of more than 7 days, recorded with its bounds only) |
| `restart_at`, `last_checkpoint` | restart | When the producer restarted and its last checkpoint |
| `replay_from`, `replay_to` | restart | Window of the replayed messages (event time) |
| `skipped_from`, `skipped_to` | restart | Window of the skipped messages; null when nothing was skipped |
| `events_replayed`, `events_skipped` | restart | Counts |
| `utc_date`, `devices` | skipped_detail | Skipped count per device for one UTC day |

## Command

```bash
make stream-up                         # Kafka, topics, and the producer
make stream-check MINUTES=60           # measured rate, CPU, memory, log growth
docker compose run --rm bioguardia-telemetry telemetry verify --from 2026-11-26T12:00:00Z --to 2026-11-26T12:20:00Z
make stream-stop
```

`ODP_TELEMETRY_RATE_SCALE` multiplies the event rate (0.1 gives a tenth) for light runs. It changes the world, so set it before the first run: the counters of the daily export follow it.
