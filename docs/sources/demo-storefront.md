# Demo storefront clickstream

| Field | Value |
| --- | --- |
| Name | Demo storefront clickstream |
| Type | Generated event log (JSONL) |
| Role | User actions on a fictional retail website, written as one reproducible batch |
| URL | None. The generator is local |
| Gold Domain | `storefront_behavior` |
| License | Generated by this repository |
| Access | CLI with seed, count, and event-time start |
| Decision | P1-07. Daily batch, weekly batch, and CDC stay on PostgreSQL |
| Related Issue | P1-07 |

One record is one user action: `page_view`, `add_to_cart`, or `purchase`. `event_id` identifies the action. `event_time` is the time of the action, in UTC, with millisecond precision and a `Z` suffix. `session_id`, `user_id`, and `product_id` are generated tokens. `product_id` is null on some `page_view` actions. Those tokens do not join Olist `product_id` or DummyJSON `id`.

The body is a pure function of `seed`, `count`, and `event_time_start`. The same three inputs always produce the same bytes. The generator truncates `event_time_start` to milliseconds in UTC, then spaces actions at 500 per second of event time (2 milliseconds apart). It does not sleep. `count` must be an integer greater than or equal to 1. One run writes one object, so a longer event clock stays in that same key. `seed` must be from 0 to 4294967295. `_ingestion_ts` stays on the object metadata. The `dt=` partition is the UTC date of that ingestion timestamp, which can differ from `event_time`.

Each run writes one object:

`raw/demo_storefront/clickstream/dt={YYYY-MM-DD}/execution_id={execution_id}/events.jsonl`

The same `--execution-id` and `--ingestion-ts` overwrite that object. A new `execution_id` keeps the previous object. This generator emits only records that match the contract, so a normal run deletes any stale quarantine object for that identity and does not write a new one. A line that is not a JSON object, or whose keys differ from the contract, fails before the write. The sidecar key for this dataset ends in `events.jsonl.jsonl` under `quarantine/demo_storefront/clickstream/`.

## Later layers

These layers are not built in P1-07. Bronze promotion is P2-03.

| Layer | Issue | Intended use |
| --- | --- | --- |
| Bronze | P2-03 | Implemented. One row per JSONL action, plus `source_id`, `execution_id`, `_ingestion_ts`, `raw_object_key`, `record_index`, and `dt`. See [bronze layer](../architecture/bronze-layer.md). The raw payload stays auditable. |
| Silver | P2-04 | Implemented in `lakehouse.silver.demo_storefront`. Typed clickstream deduplicated on `event_id`, ordered by `event_time`. A null `product_id` stays null. See [silver layer](../architecture/silver-layer.md). |
| Gold | P2-05 | Schema `storefront_behavior` in [Gold model design](../architecture/gold-model-design.md): session, product, and user behavior, plus quality findings. The generated `product_id` does not join Olist or DummyJSON. dbt models are P2-06. |

## Command

From the repository root, with `ODP_RAW_BUCKET` and MinIO settings in the environment:

```bash
uv run python -m open_data_platform.ingestion.demo_storefront \
  --execution-id run-001 \
  --seed 7 \
  --count 100 \
  --event-time-start 2026-10-18T00:00:00Z
```

`--ingestion-ts` is optional. It must be timezone-aware ISO-8601. The same value overwrites the same key.
